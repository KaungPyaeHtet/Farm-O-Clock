# Farm O'Clock (NASA Space Apps 2026 — "Field Shift: Adapting Farms with NASA Data")

Mobile-first decision-support app. A farmer pins a field anywhere on Earth. The app replays 20 years of NASA climate data
to rate drought/flood/heat risk per sowing week, recommends a sowing window with a confidence, says if the season is
Dry/Normal/Wet, compares 3 rotation strategies (Baseline / Water-Conserving / Soil-Rebuilding) with Rain and Heat
what-if sliders, and ends with an English/Burmese brief and a field-check checklist. It supports farmer judgment and must never replace it.

## Live

- Web: https://farm-oclock-five.vercel.app (Vercel project `farm-oclock`, root `web/`)
- Model API: https://farm-oclock-api.vercel.app (Vercel project `farm-oclock-api`, root `backend/`, FastAPI, `x-api-key` required)
- Deploy: `vercel deploy --prod --yes` inside `web/` or `backend/` (CLI is logged in). Env vars live in Vercel; local copies in `web/.env.local`, `backend/.env` (git-ignored).

## Layout

- `web/`: Next.js 16 + React 19 + Tailwind 4 + Leaflet. **Read `web/AGENTS.md`: Next 16 APIs differ from training data.**
  - `src/components/Wizard.tsx`: 7-step flow + state. Screens are in `src/components/screens/`:
    1 `Screen1Map`, 2 `Screen2Environment`, 3 `Screen3CropGoals`, 4 `SeasonReplay`, 5 `SowingCalendar`,
    6 `Screen5RotationCompare`, 7 `Screen6Guidance` (file numbers do not match step numbers).
  - `src/app/api/*/route.ts`: the current backend. It is server-side and has no DB or keys:
    `geocode` (Nominatim), `environment` (POWER 30-day + SRTM slope via OpenTopoData),
    `replay` (20-yr × 14-week risk grid), `history` (Dry/Normal/Wet z-score),
    `observations` (farmer reports → Supabase), `geocode/reverse` (pin → "Town, Region, Country"),
    `outlook` + `scenario` + `vegetation` + `rotation` (Python API via `lib/backend.ts`; 503 → UI hides those panels),
    `landcover` (ESA WorldCover: pins on water are refused, built-up gets a warning), `plans` (save finished plans),
    `soil` (SoilGrids), `warm` (wakes the Python API when the app opens). The plan text is a fixed template (`lib/brief.ts`); the user chose NOT to use any LLM/AI API. Calibrated "N in 10" chance:
    `lib/confidence.ts` + `lib/confidence-curve.json` (copied from `backend/models/confidence_curve.json` — keep in sync).
    `replay`/`history` cache raw POWER pulls in Supabase via `withNasaCache`.
  - UI conventions: **farmer-facing only** — no method/source/"how it's built" text in the app (that lives in `reports/`
    and the pitch deck). Every screen uses `<Screen>` from `components/Screen.tsx` (phone = 1 column, `lg:` = wide
    dashboard, max-w-6xl). Risk words come from `RISK_WORDS` in `lib/ui.ts` (Low / Some / High risk). Show place names,
    not coordinates. Past seasons: year×week heatmap on all sizes. Sowing weeks are shown as real upcoming dates via
    `lib/season.ts` (passed weeks greyed; "best" = best week still ahead). No voice/"Listen" and no LLM API (user decisions).
    Map: Esri imagery + Esri place-name labels, "Use my location", draggable pin. Finished plans → `/api/plans` (Supabase).
    Data fetching goes through `lib/fetchJson.ts` (session cache, so /api/replay is fetched once). EN/မြန်မာ toggle is in the Wizard header.
  - `src/lib/strategies.ts` (heuristic scoring, placeholder for ML) and `src/lib/brief.ts` (template, placeholder for an LLM).
    `types.ts` holds the shared response shapes.
- `supabase/schema.sql`: paste-into-SQL-editor schema (fields, plans, observations + validation trigger,
  nasa_cache, model_evals, photo bucket). RLS on, no public policies; server code uses `SUPABASE_SECRET_KEY` (`web/src/lib/supabase.ts`, server-only).
  Env: `web/.env.example`, `backend/.env.example`. App runs without them (no cache, observations return 503).
- `tasks.md`: the team's ordered checklist.
- `reports/`: accuracy report with charts (`README.md`, `figures/`, `data/`), regenerated by `backend/eval/make_figures.py`;
  any location can be backtested with `python -m eval.check_site LAT LNG`.
- `backend/`: Python. FastAPI model API (`app/main.py`: `/v1/outlook` (+ seasonal forecast), `/v1/scenario`, `/v1/vegetation`
  (MODIS NDVI via Planetary Computer point API — no rasterio, serverless-safe), `/v1/water` (FAO-56)), Dockerfile,
  logistic risk model as JSON (`models/`, refit with `train_risk.py`). Run: `.venv/bin/uvicorn app.main:app --port 8000`
  and set `BACKEND_URL=http://localhost:8000` in `web/.env.local`.
- `backend/` modules:
  - `farm/power.py` (NASA POWER client; cache in `.cache/`, `/tmp` on Vercel), `farm/replay.py` (engine; `replay_like_web`
    mirrors the TS route exactly — `tests/test_parity.py`), `farm/location.py`, `farm/seasonal.py`, `farm/vegetation.py`,
    `farm/water.py`, `farm/risk_model.py`, `farm/rotation.py` (data-driven partner crops: low-risk share + FAO-56 +
    ECOCROP temperature; `/v1/rotation`, tested in `eval/partner_eval.py`). Deps: `requirements.txt` (runtime) / `requirements-dev.txt` (eval, tests).
  - Evals: `eval/run_eval.py` (E0–E3), `improvements.py` (E4), `yield_check.py` (E5, FAOSTAT), `scale_eval.py` (E6, 73 sites),
    `make_figures.py` → `reports/figures/` (14 charts).
  - `eval/REPORT.md` = accuracy/skill results. `backend/README.md` = model plan, test plan, hosting.

## Commands

- Web: `cd web && npm install && npm run dev`
- Python: `cd backend && .venv/bin/python -m pytest` and `.venv/bin/python -m eval.run_eval` (~30 s when cached)

## Data

- **In use:** NASA POWER daily point API (`community=AG`; `PRECTOTCORR`, `T2M`, `T2M_MAX`, `GWETTOP`, `GWETROOT`; fill = -999,
  ~5-day latency), SRTM 30 m (OpenTopoData), MODIS Terra NDVI MOD13Q1 (Planetary Computer; needs ≥ 12 clear views in 4 yrs,
  else 422 and the card is hidden), SoilGrids, ESA WorldCover, Open-Meteo seasonal forecast, FAOSTAT yields/prices
  (`lib/crop-economics.json`), Nominatim + Esri map tiles.
- **Not yet used:** SMAP, GPM IMERG, ECOSTRESS, Landsat, GRACE, OpenET, market prices beyond FAOSTAT.

## Known issues (see backend/eval/REPORT.md)

- AI use is declared in `AI_DECLARATION.md` (keep it up to date).
- Fixed 2026-11-15: `api/replay` percentile ties bug (cool/arid sites were 100 % "alert"). TS and Python both use mid-rank pct, pH=0 if no hot days.
- Raw "k of 20 seasons" confidence is over-confident above 0.6. Rain/Heat sliders only affect strategy cards, not the risk grid.
- Outlook probabilities are only shown for sowing ≤ 30 days after the latest NASA data (model trained on pre-sowing conditions);
  30 days–6 months uses the Open-Meteo seasonal forecast (unvalidated). Drought model has no skill on unseen regions (E6).
- Engine = v1.1 + candidate weeks from the 1985+ record + window sums rounded to 0.01 mm. Change TS and Python together.
- Rotation scores (`strategies.ts`) and brief (`brief.ts`) are still heuristics/templates. Moving the what-if sliders shifts the
  "best" pick toward weather resilience (up to 80 % at the slider ends); at 50/50 it is the goal fit only. Lint is clean.

## Conventions

- Feature branches like `deva/<feature>` → PR to `main`. Keep EN + Burmese strings together via `t(en, my)` from `lib/i18n`.
- Keep `scoreStrategies(...)` / `buildBrief(...)` signatures stable so models can be swapped in behind them.
